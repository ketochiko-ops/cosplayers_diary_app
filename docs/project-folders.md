# プロジェクトフォルダ

Web/PWA版では、初回起動と設定画面で「指定フォルダへ自動保存」または「ブラウザ保存（Safari対応）」を選びます。

## フォルダの構成

```text
cosplayers_diary_project/
├── CosplayDiary.project.json
└── images/
    ├── photo-....png
    └── photo-....jpg
```

`CosplayDiary.project.json` に日記、ジャンル・キャラクター・衣装のマスター、カラコン台帳、画像の識別子・相対パス・元ファイル名を保存します。画像本体は `images/` に保存します。フォルダを丸ごとコピーすれば、これらをまとめて保管・移動できます。ZIPにはしません。

日々の自動保存では、追加画像を先に保存してからJSONを更新します。既存画像は変更のたびに書き直さず、JSONに画像のBase64を埋め込みません。画像の変更は新しい画像IDで保存します。

## Chrome／Edgeなどで開始する

1. 初回の「プロジェクトの保存方法」で「保存場所を指定してプロジェクトを作成」を押します。
2. 保存したい場所（親フォルダ）を選択し、ブラウザが求める読み書きの許可を与えます。その中に `cosplayers_diary_project` を作成します。同名の空フォルダを直接選んだ場合は、そのフォルダを使います。同名フォルダに既存データが入っている場合は上書きせず停止します。親フォルダにある他のファイルは変更しません。
3. 現在端末にある日記・マスター・画像を、そのフォルダへ保存して編集を開始します。
4. 既存プロジェクトを開く場合は「既存のプロジェクトフォルダを開く」で、JSONとimagesが入っているフォルダを選択します。端末と内容が異なる場合は、検証後にどちらを使うか選びます。以前に別名で作成したプロジェクトも、そのまま開けます。

変更時は自動保存します。再起動時は、保存したフォルダhandleの許可が残り、JSONが端末の控えと一致する場合だけ自動再接続します。それ以外は再指定と内容選択を求めます。保存方式と保存先は設定の「保存モード・プロジェクトフォルダを変更」から変更できます。

## 画像を追加する

日記の追加・編集画面で「画像を追加」を押し、JPEG・PNG・WebPを選びます。1枚32MB以内です。設定の「画像保存モード」に従い、原本または長辺2,048px以内で保存します。プレビューを確認し、日記を保存すると画像の参照も確定します。日記を保存せず戻った画像は日記には登録されません。

「画像を変更」では新しい画像を登録し、「画像を取り外す」では日記から参照を外します。以前の画像本体と登録済みの画像メタデータは、復旧用にプロジェクト内に残します。画像を外部アプリで同じファイル名のまま直接上書きした場合は競合として停止するため、変更は本アプリから行ってください。

Googleカレンダーには画像を送信しません。

## Safariで使う

Safariでは、任意の外部フォルダを指定して継続的に上書きする機能が利用できません。「ブラウザ保存モードで開始」を選ぶと、日記・マスターと画像をブラウザ内に自動保存します。フォルダ方式とブラウザ方式は設定から切り替えられます。

設定の「JSONファイルの控えを保存」は、画像本体もBase64で同梱する非圧縮JSONを書き出します。これを別のブラウザで読み込めば画像も移行できます。手動の控えは画像を含むため大きくなりますが、日々の自動保存にはこの形式を使いません。ブラウザデータを削除する前や端末変更時には控えを保存してください。

## 旧JSONからの移行

旧ファイル方式を使っていた場合、更新後はフォルダの再指定を求めます。端末の内容が残っているなら、そのまま空のフォルダへ作成すると日記・マスターを引き継ぎます。以前のJSONファイルは削除しません。

端末に内容が残っていない場合は、初回画面の「旧JSON・画像同梱JSONから移行」で旧JSONを読み込み、検証・確認後にフォルダを作成するかブラウザ保存を選びます。設定画面からのJSON読み込みも利用できます。旧JSONには画像本体が含まれていなかったため、旧形式だけから画像は復元できません。以前のZIPは引き続き移行読み込みのみ対応します。

## 保存先が読めなくなった場合

JSON・フォルダ・参照画像の削除、権限喪失、外部変更を検出した場合は編集と外部保存を停止し、直ちに必須の再指定画面を表示します。編集時の確認に加え、5秒間隔とアプリ復帰時にも確認します。外部変更を無条件に上書きしません。

日記・マスターと画像の控えをブラウザ内に保持するため、空の新しいフォルダを指定すると、保持できている内容を一式書き出して再開できます。画像の控えも失われている場合は、元のプロジェクトフォルダや画像同梱JSONから読み直す必要があります。

## 実装上の補足

- プロジェクトJSONは `projectFormat: 2` と `photos` を追加。旧JSONは画像一覧なしとして後方互換で読み込みます。
- 認証トークン・同期履歴・日次回数はプロジェクトに含めません。
- Webの画像の独立したコピーとdirectory handleはIndexedDB、JSONの控えはlocalStorageに保存します。Pagesの別プロジェクトとは公開パス単位で分離します。
- 画像の欠損やJSON型・画像パス不正は、ストアを置き換える前に検証します。読み込み中に外部変更が入った場合も端末の内容を保持して停止します。
- 書き込み前後のrevision確認は行いますが、別アプリとの完全なファイルシステムトランザクションではありません。途中失敗時に参照されない追加画像が残る場合はありますが、JSONを先に更新して画像を欠損させる順序にはしません。
- ネイティブ版はSQLiteとアプリ専用の画像フォルダへ保存し、画像同梱JSONでデータ交換します。外部の任意フォルダを選ぶUIは今回のWeb/PWA版が対象です。
